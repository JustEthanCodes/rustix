# Unix-like process and syscall direction

**Status: Milestone 4 is in progress. The opt-in single-vCPU diagnostic prepares separate lower-half roots for bundled init and a kernel-prepared child and runs both in Ring 3. The current implementation prepares guarded scheduler-task stacks before creating the shared process roots, runs the tasks with IF disabled, and blocks init on a process-exit queue while the scheduler runs the child. Child exit wakes init; init rechecks the wait result, copies status before reaping, and resumes on its own TSS entry stack. The first invalid status pointer returns `EFAULT` without reaping, and a retry succeeds. The path also serves ABI-version/write/close/dup/anonymous-map/exit calls, terminates CPL3 #PF/#GP/#UD/#DE with status `128 + vector`, and tears down both roots. Scheduler task stacks are reclaimed after the bounded task set exits; PID-indexed TSS entry stacks remain static. The normal kernel does not launch userspace. `just process-smoke` and `just user-fault-smoke` now validate this scheduler-backed diagnostic, including wait/reap and the CPL3 exception matrix. Userspace spawn/exec, arbitrary runnable-child scheduling, reusable process launch, interruptible wait, page-table metadata exhaustion, and broader process/runtime semantics remain incomplete.

Rustix aims to expose a small, versioned syscall surface that can support Unix-like processes and tools. The kernel must own this interface rather than inherit an ABI accidentally from a bootloader or emulator.

## Proposed compatibility principles

- Processes have independent virtual address spaces and explicit lifecycle states.
- File descriptors are per-process integer handles to kernel-managed objects; descriptor inheritance, close-on-exec, duplication, and sharing semantics must be specified together.
- Syscalls use one documented error convention and stable numeric identifiers. New operations must not silently repurpose old numbers.
- Arguments crossing privilege boundaries are copied or validated using narrowly scoped helpers. `ProcessAddressSpaceRoots::copy_from_user` and `copy_to_user` preflight the complete lower-half mapped range, check writable metadata for kernel-to-user copies, and operate only on owned frame tokens through `UserFrameMemory`; they never form a Rust reference from a user virtual address. Backend copy faults report the completed prefix. The diagnostic user-exception path terminates a process on supported CPL3 faults; it does not make arbitrary kernel memory accesses recoverable.
- Blocking, interruption, cancellation, and restart behavior are explicit for each syscall class.
- A compatibility layer (for example, POSIX-shaped libc behavior) remains separate from internal kernel APIs.

## Initial syscall ABI v1 contract (specified; register decoding implemented)

ABI version `1.0` is identified by `abi_version()`, syscall number `0`, returning `0x0001_0000` in `RAX`. In v1, `RAX` returns a signed 64-bit result: nonnegative values are success (including byte counts, addresses, and PIDs); errors are negative stable error numbers. ABI versioning is append-only: existing syscall numbers, argument meanings, layouts, and error values never change or get reused. There is no POSIX compatibility claim. `src/syscall.rs` implements the stable number/error constants, host-tested request decoding and bounded write service, and the assembly-matched syscall context layout. The workspace crate `crates/rustix-user` provides typed `no_std` wrappers for ABI version, write, wait, exit, close, descriptor duplication, one-page and bounded multi-page anonymous mappings plus a raw register-level call for low-level tests; it also provides a `run_main` entry helper and an optional mmap-backed `GlobalAlloc` implementation. Error decoding, short-write handling, formatting, region handling, and the size-class heap core are host-tested. `interrupts.rs` installs the DPL-3 gate and dedicated entry stub. The opt-in diagnostic process runtime dispatches ABI-version, bounded descriptor-authorized write, close, duplication, one-page and multi-page anonymous map/unmap, exit, and wait. If wait finds its one kernel-prepared child running, it blocks the parent scheduler task on a process-exit queue while the child task runs, then resumes the parent after exit; other running-child configurations are unsupported. QEMU init checks that mappings are zeroed, writable across page boundaries, exactly unmapped, and no longer readable by the kernel copy path afterward. It also verifies real child Ring 3 entry/exit and status 7, invalid-pointer `EFAULT` without reaping, and successful wait/status-copyout on retry. This validates the bounded diagnostic execution path, not general concurrent process scheduling or a userspace process-creation syscall. A separate kernel-side harness waits for init after its exit trampoline returns.

| Number | Call | Register arguments | Result / behavior |
| --- | --- | --- | --- |
| 0 | `abi_version` | none | `0x0001_0000` (major 1, minor 0). |
| 1 | `exit` | `RDI`: signed 32-bit status in the low 32 bits (upper bits ignored) | Does not return; status is retained exactly by the parent wait record. |
| 2 | `write` | `RDI`: fd, `RSI`: user buffer, `RDX`: byte length | Returns bytes accepted; a short positive result is valid. Initial descriptors 1 and 2 are stdout/stderr console streams; other descriptors return `-EBADF`. Maximum request is 4096 bytes; zero length returns 0 without validating the pointer. |
| 3 | `wait` | `RDI`: child PID (0 means any child), `RSI`: optional user pointer to signed 32-bit exit status | ABI contract: blocks until a matching child exits and returns its PID. A non-null status output must be writable before the child is reaped; no matching child returns `-ECHILD`. The diagnostic supports an already-exited child and one kernel-prepared running child, blocking the parent task and scheduling that child before resuming; other running-child cases return `-ENOTSUP`. Failed status copyout returns `-EFAULT` without reaping. |
| 4 | `mmap` | `RDI`: requested byte length, `1..=4096` | Maps one zero-filled, read/write, non-executable anonymous page and returns its user address. Lengths above one page return `-E2BIG`; the first-fit address comes from the bounded anonymous region window; exhaustion returns `-ENOMEM`. |
| 5 | `munmap` | `RDI`: page-aligned anonymous base, `RSI`: exactly `4096` | Removes one exact page previously allocated by `mmap`; invalid addresses, lengths, or non-anonymous regions return `-EINVAL`. |
| 6 | `close` | `RDI`: descriptor | Closes one process-local descriptor; invalid or already-closed descriptors return `-EBADF`. |
| 7 | `dup` | `RDI`: source descriptor | Duplicates the stream into the lowest free descriptor slot at or above 3; invalid descriptors return `-EBADF`, and the fixed table limit returns `-EMFILE`. |
| 8 | `mmap_region` | `RDI`: requested byte length, `1..=1 MiB` | Maps a contiguous, zero-filled RW/NX anonymous region, rounding length up to 4 KiB. Returns its base; reservation, frame, or page-table exhaustion returns `-ENOMEM`. |
| 9 | `munmap_region` | `RDI`: exact region base, `RSI`: exact page-rounded region length | Unmaps one exact anonymous region returned by `mmap_region`; invalid ranges, lengths, or non-anonymous regions return `-EINVAL`. |

Numbers above 9 are unassigned and return `-ENOSYS`; assigning a number later is an additive extension, never a reinterpretation. `mmap`, `munmap`, `mmap_region`, `munmap_region`, `close`, and `dup` are available only in the opt-in diagnostic process runtime today. Descriptor 0 is reserved for input but v1 has no `read` or `open` call. Descriptors 1 and 2 start as stdout/stderr; child process records inherit the parent's current console-descriptor table, duplication creates an independent handle to the same stream, and process exit clears its descriptor table. The initial process is created by the kernel loader, not a syscall.

Stable v1 error numbers (returned negated in `RAX`) are: `1 EINVAL`, `2 EBADF`, `3 EFAULT`, `4 ENOMEM`, `5 ECHILD`, `6 EINTR`, `7 EIO`, `8 ENOSYS`, `9 E2BIG`, `10 EOVERFLOW`, and `11 ENOTSUP`, and `12 EMFILE`. Unknown syscall numbers return `-ENOSYS`. Pointer-plus-length ranges use checked arithmetic and must lie wholly in a mapped lower-half user range. `write` preflights the whole input range before output; a later endpoint failure may return a short count, and an error before progress returns `-EIO`. A copy fault after progress returns the completed prefix. An unmapped diagnostic `write` buffer returns `-EFAULT` before the syscall returns to userspace. `mmap` rounds any positive length up to one page, zeroes its frame before publication, and grants RW/NX access. The append-only `mmap_region`/`munmap_region` calls add exact multi-page anonymous mappings bounded to 1 MiB; mapping rolls back mapped pages and the reservation if allocation fails. Both unmap operations are restricted to exact anonymous reservations, and the kernel switches to its supervisor root, removes each PTE, and only releases each frame after the page table no longer references it. For `wait`, the optional status is copied before the matching exited child is reaped; failed copyout returns `-EFAULT` and leaves the child waitable. The diagnostic blocks the parent scheduler task on a process-exit queue when wait observes its one kernel-prepared child running, then resumes the parent after exit. This is scheduler-backed cooperative blocking for the bounded diagnostic only; arbitrary process launch/scheduling, interruption, signals, asynchronous delivery, and automatic syscall restart remain future work.

All ABI integers are fixed-width little-endian x86_64 values. The wait status is one signed 32-bit integer with no implicit padding or extra fields. No other user-visible structs exist in v1.

## Initial x86_64 entry design (Milestone 4; diagnostic path integrated)

The opt-in single-vCPU process probe enters Ring 3 with a validated five-word `IRETQ` frame and enters the kernel with `int $0x80` through a dedicated DPL-3 IDT gate. This intentionally avoids `SYSCALL`/`SYSRET`, `STAR`/`LSTAR`/`FMASK`, and `SWAPGS` state transitions in this first slice. The register and error contract below is the versioned v1 ABI, but the syscall surface and runtime are not general-purpose or enabled in the default boot path. The `rustix-user` crate includes typed wrappers, the `run_main` process-entry helper, complete-write and allocation-free formatting helpers, best-effort panic reporting, and an optional mmap-backed global allocator. The allocator obtains zeroed pages through `mmap`, serves power-of-two classes from 16 through 2048 bytes, rejects larger or over-aligned requests, and retains pages until process teardown; applications opt in by declaring `UserAllocator` as their global allocator. The runtime also exposes bounded multi-page `mmap_region`/`munmap_region` wrappers, validated by `rustix-init` across a page boundary. `rustix-init` exercises the entry helper and heap with `Vec` and `Box`, but the crate remains an early runtime and is not a general application or process-scheduling environment.

- **Vector ownership:** `0x80` lies inside the device-vector range (`0x20..=0xef`) and is reserved by `InterruptVectorAllocator`; generic IRQ allocation/release cannot claim it. The IDT installs a dedicated DPL-3 interrupt gate rather than the generic device-IRQ stub. Its assembly entry rejects CPL0 invocation, saves all GPRs and x87/SSE state, clears the direction flag, and calls a normalized Rust dispatcher with IF clear. The opt-in process probe implements ABI-version discovery, write, exit, one-page and multi-page mapping, and wait. Its one kernel-prepared child runs as a separate scheduler task; PID-indexed TSS entry stacks remain static, and this does not provide userspace spawn/exec or arbitrary child scheduling.
- **Selectors:** the current GDT uses `0x08` for kernel code, `0x10` for kernel data, and `0x18` for the two-slot TSS descriptor. Ring-3 data and 64-bit code descriptors are appended at GDT indexes 5 and 6, with compile-time selector assertions for user data `0x2b` and user code `0x33` (RPL 3); the process probe uses these selectors in its validated entry frame.
- **Privilege stack:** a CPL3-to-CPL0 interrupt uses `TSS.RSP0`. The current QEMU probe selects bounded static 16 KiB supervisor TSS entry stacks by process ID from kernel BSS and verifies every page is writable, NX, and supervisor-only in the kernel root. `TSS.RSP0` follows the active process. Separate scheduler-owned guarded kernel-task stacks suspend and resume syscall contexts; those task stacks are reclaimed after both diagnostic tasks exit, but the PID-indexed TSS entry stacks are not reclaimed. Each `enter_user` call has a separate entry-state record for its saved kernel RSP, exit status, callback context, prior nested entry, and kernel FXSAVE image; the child exit trampoline restores the parent's record. Process roots share these validated upper-half mappings. After init's exit trampoline returns to the bootstrap stack, the probe restores bootstrap `RSP0`. The static TSS entry slots are not reclaimed, and the diagnostic handles only the prepared child; arbitrary process creation and per-process lifecycle/reclamation remain future work. Callers must disable local interrupts and guarantee the stack is mapped writable in every address space that can run until the next update. A future SMP design needs per-CPU TSS and entry-stack state.
- **Entry frame and state:** the dedicated assembly stub saves all GPRs in the `SyscallContext` layout, passes the five-word privilege frame separately from the exception frame, and saves/restores x87/SSE state around the Rust dispatcher; AVX remains disabled under the current CPU-state policy. Per-entry records hold continuation RSP, exit state, callback context, the prior nested entry, and kernel FXSAVE state instead of shared depth-indexed globals. The scheduler selects among these per-entry records through cooperative task contexts; timer preemption remains disabled while user code runs. Kernel code runs with the direction flag clear. The process probe validates saved RIP/RSP against the active process mappings and accesses user buffers only through owned frame tokens. The diagnostic wait blocks the parent scheduler task while one prepared child runs; this bounded integration does not provide general userspace process scheduling.
- **Initial register convention:** `RAX` carries the syscall number; arguments use `RDI`, `RSI`, `RDX`, `R10`, `R8`, and `R9`; `RAX` carries the result. This convention and its initial numbers/errors are versioned as ABI v1. Implemented operations remain a subset of the documented contract.
- **Return validation:** use `IRETQ`, not `SYSRET`. Initial entry uses a host-tested frame sanitizer that requires exact ring-3 selectors, a canonical lower-half instruction pointer, a lower-half stack range, 16-byte initial stack alignment, and safe flags. Syscall resume uses a separate sanitizer that keeps exact selectors, canonical lower-half address shape, and privileged-flag checks but does not impose 16-byte alignment on an in-function RSP; it replaces user flags with `0x2` (IF remains clear). Once a process is active, the dispatcher also validates the saved instruction pointer against an executable mapping and the saved stack pointer against a writable NX mapping. A malformed frame is converted into process exit rather than returned to CPL3.
- **NMI and interrupt policy:** no GS-base swap is needed on this entry path. NMI, double fault, and machine check remain fatal even when their saved CS indicates CPL3. Other user-origin exceptions terminate the process with status `128 + vector` in the diagnostic runtime; QEMU exercises CPL3 #PF/#GP/#UD/#DE. Kernel-origin #PF/#GP/#UD/#DE are separately tested as fatal. Ordinary maskable IRQs stay disabled throughout user-task execution; scheduler switches occur only at explicit cooperative waits and exits.

This path depends on each process root sharing supervisor-only upper-half mappings that cover syscall/exception code, the IDT, GDT, TSS, and active kernel stacks. The bundled init/child roots and nested syscall/exception transitions are exercised by opt-in QEMU smokes, but the shared Limine-derived kernel mapping is not a curated kernel map or a general isolation policy. Do not enable normal boot-time Ring 3 execution until userspace process creation, scheduler-managed user contexts, scheduler-owned/reclaimed per-process kernel stacks, general wait-queue semantics, and the remaining Milestone 4 fault/teardown criteria are implemented and validated.

### Process address spaces (design; root construction partially implemented)

Use a separate four- or five-level root per process. The initial source is the retained active clone of Limine's hierarchy, not a curated clean-room root. Each process root owns its root page, all lower-half intermediate tables, and every user leaf frame. Keep the kernel-root owner alive for the lifetime of every process root. Copy only upper-half top-level entries from that owner into each process root; these entries are non-owning references to shared kernel subtrees, not deep copies, and must never be released by a process teardown. Do not copy lower-half entries from the kernel root.

Before publishing a shared kernel subtree, validate its page-table structure and physical bounds and reject any effectively user-accessible leaf. U/S permission is the conjunction of every entry on a path, so a U/S bit on one non-leaf alone does not grant user access. When copying upper-half root entries, clear their U/S bit as defense in depth; a user leaf then cannot become accessible if a lower entry changes. `paging::validate_supervisor_kernel_half` implements the bounded, read-only structural/effective-permission preflight, but it does not install roots or prove physical backing is readable; the supplied reader must provide that access guarantee. Sharing the active clone means every accepted upper-half supervisor mapping and alias is present in every process CR3. This is not a curated kernel map or kernel-page-table isolation, and it provides no transient-execution protection. User mappings remain private to one process, are confined to the lower canonical half, preserve W^X, and are non-global in the first implementation.

The kernel address-space owner is the only authority allowed to modify shared upper-half tables. Mutations must be serialized with local interrupts disabled on the current single-vCPU system and invalidate the affected local translation before the mapping change is relied on. A process root may not edit or reclaim shared tables. `ProcessAddressSpaceRoots::destroy` releases only private user leaves, intermediate tables, and the root; the caller must first switch CR3 to a different live root and invalidate this root's local non-global translations. Keep the shared kernel owner alive. PCID-aware invalidation and SMP shootdown remain unsupported and need a separate design.

The current `CandidatePageTables` deep-clones the inherited hierarchy, tracks all cloned tables as owned, and holds an exclusive mutable borrow of one memory backend; it is not itself the process-address-space abstraction. `SharedKernelHalf` validates and snapshots the sanitized upper root entries while borrowing the kernel owner. `ProcessAddressSpaceRoots` uses one exclusive backend borrow for multiple private roots, maps allocator-owned user 4 KiB leaves only in inactive lower halves, retains writable/executable permission metadata, validates the initial executable entry and writable NX stack, provides range-preflighted copy-in/copy-out through a separate `UserFrameMemory` backend, and destroys private leaf/table/root frames without freeing shared subtrees. Host tests cover four-/five-level sharing, U/S sanitization, independent mappings, permission checks, cross-page copies, unmap ownership, active-root release rejection, and rollback. The opt-in `probe-user-process` target constructs separate init and child roots, loads two bundled static ELFs, and runs them as cooperative scheduler tasks. It switches CR3 and TSS entry stacks around each user entry; when wait observes the prepared child running, init blocks on the process-exit queue and resumes after child exit. Wait-status copyout precedes reap, and CR3 is restored before kernel wait/reap and teardown. The bounded probe reclaims scheduler-owned task stacks after both tasks exit, but retains PID-indexed static TSS entry stacks and the Limine-derived shared kernel subtree; it is not a general userspace launcher or curated kernel-map policy. Keep the kernel owner alive and immutable for the shared view's lifetime; callers must use a distinct page-table backend for process-owned tables.

### Static ELF64 image validation and page initialization (partial)

`src/elf.rs` parses little-endian x86_64 `ET_EXEC` images without allocation. It bounds the program-header count, load-segment count, and total mapped pages; checks file and virtual arithmetic, page alignment and `p_align` congruence, lower-half canonical ranges, non-overlapping page spans, readable segment flags, W^X, and that the entry point lies in a non-writable executable `PT_LOAD`. It rejects dynamic/interpreter and TLS segments and executable-stack requests. This initial format intentionally requires page-aligned load offsets/addresses and supports at most 64 program headers, 16 load segments, and 64 load pages. `populate_segment_page` copies one load page into an allocator-owned frame through `UserFrameMemory`, zero-filling bytes beyond the file payload. `load_into_process_root` allocates, populates, cache-selects, and maps every load page into an inactive process root. The diagnostic build reproducibly compiles `crates/rustix-init` as a static ELF64 payload; `just process-smoke` loads and runs the normal image, and `just user-fault-smoke` builds a `ud2` entry variant and validates process termination/reaping/teardown.

## ABI decisions still pending beyond v1

The initial v1 versioning, error encoding, syscall numbers, register-level request decoding, and assembly-matched syscall context layout are implemented in `src/syscall.rs`. The diagnostic `int 0x80` path sanitizes return frames and serves ABI-version, bounded descriptor-authorized write, close/dup, wait, one-page and multi-page mmap/munmap, and exit calls; invalid unmapped write/status buffers return `EFAULT` without corrupting the process or consuming a waitable child. `src/process.rs` provides fixed-capacity identity/exit-state policy. The userspace wait blocks init's scheduler task on a process-exit queue when its one kernel-prepared child is still running, resumes after child exit, and copies status before reaping; QEMU validation of this scheduler-backed path is pending. The kernel harness separately waits for init after its entry trampoline returns. This does not implement a userspace process-creation syscall, scheduler-managed user contexts, arbitrary child scheduling, or interruptible wait. The fixed-capacity process table now tracks stdout/stderr console handles, child inheritance, duplicate slots, close, exit cleanup, and bounded-table exhaustion; these are not general file objects, and there is no read/open support. User faults are process-terminating only while the opt-in callback is installed; QEMU covers CPL3 #PF/#GP/#UD/#DE and kernel-fatal coverage for the same four vectors. This does not make arbitrary kernel accesses recoverable. Still to be specified before broader process operations are process-creation/exec and file-action semantics, general descriptor-object sharing and close-on-exec behavior, read/open support, blocking wait interruption, signal-like asynchronous delivery, clocks, and any additional structure layouts.

## Suggested first user-visible slice

The first controlled `no_std` init and a separately bundled child run only in the opt-in QEMU probe. Init exercises ABI-version discovery, descriptor duplication/write/close, EFAULT, a blocking wait that schedules the real child as a separate task, status-copyout retry, one-page and multi-page mmap/munmap, `Vec`/`Box` allocation, exit, kernel-side wait/reap, and teardown. The child writes a marker and exits with status 7; QEMU verifies the parent's retry reaps it. `rustix-user` provides typed wrappers, a process-entry helper, short-write handling, allocation-free formatting, panic exit, and an optional size-class allocator backed by mmap. This remains a diagnostic rather than a general process-execution environment: userspace spawn/exec, arbitrary runnable children, reclaimable per-process TSS entry stacks, and page-table metadata exhaustion tests remain work before a normal-boot userspace service. Read/write/open/close and descriptor-lifetime semantics need their own complete implementation and adversarial tests before any Unix-compatibility claim.
