# Unix-like process and syscall direction

**Status: bounded single-vCPU Milestone 4 implementation validated.** Default boot launches a controlled Ring 3 `rustix-init`; the process smoke additionally exercises generation-safe slot reuse, child-originated nested spawn, orphan cleanup, and append-only `exec` (syscall 11). Spawn copies a bounded ELF image into kernel-owned staging before returning, prepares a private root, guard, and 1–16-page zeroed stack, then publishes a cooperative task. The QEMU smokes validate process teardown, status-copyout retry, exec replacement and old-image reclamation, and malformed syscall-return termination. The runtime remains deliberately bounded to four concurrent processes, cooperative with IF disabled, and single-vCPU. General-purpose process scheduling, curated kernel mappings, SMP, and physical-hardware validation remain future work.

Rustix aims to expose a small, versioned syscall surface that can support Unix-like processes and tools. The kernel must own this interface rather than inherit an ABI accidentally from a bootloader or emulator.

## Proposed compatibility principles

- Processes have independent virtual address spaces and explicit lifecycle states.
- File descriptors are per-process integer handles to kernel-managed objects; descriptor inheritance, close-on-exec, duplication, and sharing semantics must be specified together.
- Syscalls use one documented error convention and stable numeric identifiers. New operations must not silently repurpose old numbers.
- Arguments crossing privilege boundaries are copied or validated using narrowly scoped helpers. `ProcessAddressSpaceRoots::copy_from_user` and `copy_to_user` preflight the complete lower-half mapped range, check writable metadata for kernel-to-user copies, and operate only on owned frame tokens through `UserFrameMemory`; they never form a Rust reference from a user virtual address. Backend copy faults report the completed prefix. The diagnostic user-exception path terminates a process on supported CPL3 faults; it does not make arbitrary kernel memory accesses recoverable.
- Blocking, interruption, cancellation, and restart behavior are explicit for each syscall class.
- A compatibility layer (for example, POSIX-shaped libc behavior) remains separate from internal kernel APIs.

## Initial syscall ABI v1 contract (specified; register decoding implemented)

ABI version `1.1` is identified by `abi_version()`, syscall number `0`, returning `0x0001_0001` in `RAX`. In v1, `RAX` returns a signed 64-bit result: nonnegative values are success (including byte counts, addresses, and PIDs); errors are negative stable error numbers. ABI versioning is append-only: existing syscall numbers, argument meanings, layouts, and error values never change or get reused. There is no POSIX compatibility claim. `src/syscall.rs` implements stable number/error constants, request decoding, and the assembly-matched syscall context layout. The `crates/rustix-user` crate provides typed `no_std` wrappers, including bounded `spawn` and `exec`, plus process entry, I/O, formatting, panic, and optional mmap-backed allocation helpers; host tests cover decoding, wrapper limits, I/O formatting, and allocator behavior. Default boot launches the controlled init; QEMU process variants exercise the implemented calls listed below. Active processes may spawn up to the four-process capacity from user-memory ELF images. The kernel copies each complete bounded image before returning, so the source can be unmapped immediately. Spawn prepares the child root before publishing its context to a cooperative task. Wait blocks the caller while a matching child runs and resumes to copy status, reclaim the inactive child root, then reap. The QEMU smoke validates nested children, malformed-image and invalid-source rejection, a two-page zeroed child stack, task-capacity exhaustion, source unmapping before child execution, status-copyout retry, per-child root reclamation, and final teardown. This is bounded single-vCPU support, not general-purpose process scheduling.

| Number | Call | Register arguments | Result / behavior |
| --- | --- | --- | --- |
| 0 | `abi_version` | none | `0x0001_0001` (major 1, minor 1). |
| 1 | `exit` | `RDI`: signed 32-bit status in the low 32 bits (upper bits ignored) | Does not return; status is retained exactly by the parent wait record. |
| 2 | `write` | `RDI`: fd, `RSI`: user buffer, `RDX`: byte length | Returns bytes accepted; a short positive result is valid. Initial descriptors 1 and 2 are stdout/stderr console streams; other descriptors return `-EBADF`. Maximum request is 4096 bytes; zero length returns 0 without validating the pointer. |
| 3 | `wait` | `RDI`: child PID (0 means any child), `RSI`: optional user pointer to signed 32-bit exit status | ABI contract: blocks until a matching child exits and returns its PID. A non-null status output must be writable before the child is reaped; no matching child returns `-ECHILD`. The diagnostic supports already-exited children and its fixed set of kernel-prepared running children, blocking the parent task and scheduling them before resuming. Failed status copyout returns `-EFAULT` without reaping or releasing the child's root; successful copyout is followed by inactive-root teardown and then record reaping. |
| 4 | `mmap` | `RDI`: requested byte length, `1..=4096` | Maps one zero-filled, read/write, non-executable anonymous page and returns its user address. Lengths above one page return `-E2BIG`; the first-fit address comes from the bounded anonymous region window; exhaustion returns `-ENOMEM`. |
| 5 | `munmap` | `RDI`: page-aligned anonymous base, `RSI`: exactly `4096` | Removes one exact page previously allocated by `mmap`; invalid addresses, lengths, or non-anonymous regions return `-EINVAL`. |
| 6 | `close` | `RDI`: descriptor | Closes one process-local descriptor; invalid or already-closed descriptors return `-EBADF`. |
| 7 | `dup` | `RDI`: source descriptor | Duplicates the stream into the lowest free descriptor slot at or above 3; invalid descriptors return `-EBADF`, and the fixed table limit returns `-EMFILE`. |
| 8 | `mmap_region` | `RDI`: requested byte length, `1..=1 MiB` | Maps a contiguous, zero-filled RW/NX anonymous region, rounding length up to 4 KiB. Returns its base; reservation, frame, or page-table exhaustion returns `-ENOMEM`. |
| 9 | `munmap_region` | `RDI`: exact region base, `RSI`: exact page-rounded region length | Unmaps one exact anonymous region returned by `mmap_region`; invalid ranges, lengths, or non-anonymous regions return `-EINVAL`. |
| 10 | `spawn` | `RDI`: user ELF image pointer, `RSI`: image length (`1..=1 MiB`), `RDX`: initial stack pages (`1..=16`) | Copies the complete read-only user range into kernel staging, validates and loads a static ELF64 image into a private root, prepares a guard and zeroed RW/NX stack, and returns the child PID. Invalid pointers return `-EFAULT`; malformed ELF/stack arguments return `-EINVAL`; resource exhaustion returns `-ENOMEM`. Any active process in the controlled runtime may spawn; four process slots (including init) bound concurrent processes. |
| 11 | `exec` | `RDI`: user ELF image pointer, `RSI`: image length (`1..=1 MiB`), `RDX`: initial stack pages (`1..=16`) | Replaces the caller's root, image, and stack with a new static ELF image. On success the syscall does not return; the process resumes Ring 3 at the replacement image's entry with a fresh zeroed stack, preserving PID, descriptors, parent, and children. Malformed images return `-EINVAL`, invalid pointers `-EFAULT`, and resource failures `-ENOMEM`; the original image remains usable. The user x87/SSE state is preserved across a successful exec. |

Numbers above 11 are unassigned and return `-ENOSYS`; assigning a number later is an additive extension, never a reinterpretation. `mmap`, `munmap`, `mmap_region`, `munmap_region`, `spawn`, `close`, and `dup` are available in the controlled process runtime used by the default bundled init; this is not a general application loader. Descriptor 0 is reserved for input but v1 has no `read` or `open` call. Descriptors 1 and 2 start as stdout/stderr; child process records inherit the parent's current console-descriptor table, duplication creates an independent handle to the same stream, and process exit clears its descriptor table. The initial process is created by the kernel loader, not a syscall.

Stable v1 error numbers (returned negated in `RAX`) are: `1 EINVAL`, `2 EBADF`, `3 EFAULT`, `4 ENOMEM`, `5 ECHILD`, `6 EINTR`, `7 EIO`, `8 ENOSYS`, `9 E2BIG`, `10 EOVERFLOW`, `11 ENOTSUP`, and `12 EMFILE`. Unknown syscall numbers return `-ENOSYS`. Pointer-plus-length ranges use checked arithmetic and must lie wholly in a mapped lower-half user range. `write` preflights the whole input range before output; a later endpoint failure may return a short count, and an error before progress returns `-EIO`. A copy fault after progress returns the completed prefix. `mmap`/`mmap_region` provide zeroed RW/NX mappings; multi-page region mapping is bounded to 1 MiB and rolls back on failure. Unmap operations require an exact anonymous reservation, and the kernel releases frames only after removing their PTEs. `spawn` preflights and copies the complete bounded image from the caller through owned frame tokens into fixed kernel staging before ELF parsing; it does not retain the caller pointer. An invalid source returns `-EFAULT`, malformed static ELF or stack layout returns `-EINVAL`, and capacity/resource failures return `-ENOMEM`. `wait` copies optional status before reaping; failed copyout returns `-EFAULT` and leaves the child waitable. The diagnostic blocks the parent task on a process-exit queue when a matching child is running, then resumes and rechecks the requested PID. It supports the fixed pre-reserved task set only; arbitrary process launch/scheduling, interruption, signals, asynchronous delivery, and automatic syscall restart remain future work.

All ABI integers are fixed-width little-endian x86_64 values. The wait status is one signed 32-bit integer with no implicit padding or extra fields. No other user-visible structs exist in v1.

## Initial x86_64 entry design (Milestone 4; bounded runtime integrated)

The bounded single-vCPU process runtime enters Ring 3 with a validated five-word `IRETQ` frame and enters the kernel with `int $0x80` through a dedicated DPL-3 IDT gate. Default boot launches the controlled bundled init; diagnostic QEMU variants exercise additional process and fault cases. This intentionally avoids `SYSCALL`/`SYSRET`, `STAR`/`LSTAR`/`FMASK`, and `SWAPGS` state transitions. The register and error contract below is the versioned v1 ABI, but the syscall surface and runtime are not general-purpose. The `rustix-user` crate includes typed wrappers, the `run_main` process-entry helper, complete-write and allocation-free formatting helpers, best-effort panic reporting, and an optional mmap-backed global allocator. The allocator obtains zeroed pages through `mmap`, serves power-of-two classes from 16 through 2048 bytes, rejects larger or over-aligned requests, and retains pages until process teardown; applications opt in by declaring `UserAllocator` as their global allocator. The runtime also exposes bounded multi-page `mmap_region`/`munmap_region` wrappers, validated by `rustix-init` across a page boundary. `rustix-init` exercises the entry helper and heap with `Vec` and `Box`, but the crate remains an early runtime and is not a general application or process-scheduling environment.

- **Vector ownership:** `0x80` lies inside the device-vector range (`0x20..=0xef`) and is reserved by `InterruptVectorAllocator`; generic IRQ allocation/release cannot claim it. The IDT installs a dedicated DPL-3 interrupt gate rather than the generic device-IRQ stub. Its assembly entry rejects CPL0 invocation, saves all GPRs and x87/SSE state, clears the direction flag, and calls a normalized Rust dispatcher with IF clear. The controlled runtime implements ABI-version discovery, write, exit, anonymous mappings, spawn, wait, and exec. Active processes can create children as distinct cooperative scheduler tasks from copied user images; concurrent process capacity is fixed at four. Per-task TSS entry stacks are allocator-backed, reusable, and reclaimed when tasks are reaped. This remains a bounded runtime, not a general userspace scheduler.
- **Selectors:** the current GDT uses `0x08` for kernel code, `0x10` for kernel data, and `0x18` for the two-slot TSS descriptor. Ring-3 data and 64-bit code descriptors are appended at GDT indexes 5 and 6, with compile-time selector assertions for user data `0x2b` and user code `0x33` (RPL 3); the process probe uses these selectors in its validated entry frame.
- **Privilege stack:** a CPL3-to-CPL0 interrupt uses `TSS.RSP0`. Each process task owns bounded allocator-backed scheduler and TSS entry stacks; the kernel maps them supervisor-only, writable, and NX. `TSS.RSP0` follows the active task. Scheduler-owned stacks are reclaimed after task exit and their bounded slots can be reused. Each `enter_user` call has a separate entry-state record for its saved kernel RSP, exit status, callback context, prior nested entry, and kernel FXSAVE image; the exit trampoline restores the correct record. Process roots share the validated upper-half mappings. After init's exit trampoline returns to the bootstrap stack, the probe restores bootstrap `RSP0`. The four process slots permit init plus up to three concurrent descendants; task and TSS entry-stack resources are reusable within that fixed capacity. Callers must disable local interrupts and guarantee the stack is mapped writable in every address space that can run until the next update. A future SMP design needs per-CPU TSS and entry-stack state.
- **Entry frame and state:** the dedicated assembly stub saves all GPRs in the `SyscallContext` layout, passes the five-word privilege frame separately from the exception frame, and saves/restores x87/SSE state around the Rust dispatcher; AVX remains disabled under the current CPU-state policy. Per-entry records hold continuation RSP, exit state, callback context, the prior nested entry, and kernel FXSAVE state instead of shared depth-indexed globals. The scheduler selects among these records through cooperative task contexts; timer preemption remains disabled while user code runs. Kernel code runs with the direction flag clear. The process runtime validates saved RIP/RSP against the active process mappings and accesses user buffers only through owned frame tokens. Spawn copies bytes before publishing a child; wait can block and recheck any matching child in the bounded pre-reserved set. General userspace scheduling is not provided.
- **Initial register convention:** `RAX` carries the syscall number; arguments use `RDI`, `RSI`, `RDX`, `R10`, `R8`, and `R9`; `RAX` carries the result. This convention and its initial numbers/errors are versioned as ABI v1. Implemented operations remain a subset of the documented contract.
- **Return validation:** use `IRETQ`, not `SYSRET`. Initial entry uses a host-tested frame sanitizer that requires exact ring-3 selectors, a canonical lower-half instruction pointer, a lower-half stack range, 16-byte initial stack alignment, and safe flags. Syscall resume uses a separate sanitizer that keeps exact selectors, canonical lower-half address shape, and privileged-flag checks but does not impose 16-byte alignment on an in-function RSP; it replaces user flags with `0x2` (IF remains clear). Once a process is active, the dispatcher also validates the saved instruction pointer against an executable mapping and the saved stack pointer against a writable NX mapping. A malformed frame is converted into process exit rather than returned to CPL3.
- **NMI and interrupt policy:** no GS-base swap is needed on this entry path. NMI, double fault, and machine check remain fatal even when their saved CS indicates CPL3. Other user-origin exceptions terminate the process with status `128 + vector` while the process callback is installed; QEMU exercises CPL3 #PF/#GP/#UD/#DE. Kernel-origin #PF/#GP/#UD/#DE are separately tested as fatal. Ordinary maskable IRQs stay disabled throughout user-task execution; scheduler switches occur only at explicit cooperative waits and exits.

This path depends on each process root sharing supervisor-only upper-half mappings that cover syscall/exception code, the IDT, GDT, TSS, and active kernel stacks. The default init and spawn-created child roots plus nested syscall/exception transitions are exercised by QEMU smokes, but the shared Limine-derived kernel mapping is not a curated kernel map or a general isolation policy. Default boot launches the controlled init runtime. This does not provide general process scheduling or isolation from the shared Limine-derived kernel mapping.

### Process address spaces (bounded implementation)

Use a separate four- or five-level root per process. The initial source is the retained active clone of Limine's hierarchy, not a curated clean-room root. Each process root owns its root page, all lower-half intermediate tables, and every user leaf frame. Keep the kernel-root owner alive for the lifetime of every process root. Copy only upper-half top-level entries from that owner into each process root; these entries are non-owning references to shared kernel subtrees, not deep copies, and must never be released by a process teardown. Do not copy lower-half entries from the kernel root.

Before publishing a shared kernel subtree, validate its page-table structure and physical bounds and reject any effectively user-accessible leaf. U/S permission is the conjunction of every entry on a path, so a U/S bit on one non-leaf alone does not grant user access. When copying upper-half root entries, clear their U/S bit as defense in depth; a user leaf then cannot become accessible if a lower entry changes. `paging::validate_supervisor_kernel_half` implements the bounded, read-only structural/effective-permission preflight, but it does not install roots or prove physical backing is readable; the supplied reader must provide that access guarantee. Sharing the active clone means every accepted upper-half supervisor mapping and alias is present in every process CR3. This is not a curated kernel map or kernel-page-table isolation, and it provides no transient-execution protection. User mappings remain private to one process, are confined to the lower canonical half, preserve W^X, and are non-global in the first implementation.

The kernel address-space owner is the only authority allowed to modify shared upper-half tables. Mutations must be serialized with local interrupts disabled on the current single-vCPU system and invalidate the affected local translation before the mapping change is relied on. A process root may not edit or reclaim shared tables. `ProcessAddressSpaceRoots::destroy` releases only private user leaves, intermediate tables, and the root; the caller must first switch CR3 to a different live root and invalidate this root's local non-global translations. Keep the shared kernel owner alive. PCID-aware invalidation and SMP shootdown remain unsupported and need a separate design.

The current `CandidatePageTables` deep-clones the inherited hierarchy, tracks all cloned tables as owned, and holds an exclusive mutable borrow of one memory backend; it is not itself the process-address-space abstraction. `SharedKernelHalf` validates and snapshots the sanitized upper root entries while borrowing the kernel owner. `ProcessAddressSpaceRoots` uses one exclusive backend borrow for multiple private roots, maps allocator-owned user 4 KiB leaves only in inactive lower halves, retains writable/executable permission metadata, validates the initial executable entry and writable NX stack, provides range-preflighted copy-in/copy-out through a separate `UserFrameMemory` backend, and destroys private leaf/table/root frames without freeing shared subtrees. Host tests cover four-/five-level sharing, U/S sanitization, independent mappings, permission checks, cross-page copies, unmap ownership, active-root release rejection, and rollback. The default boot path prepares the init root; the process-smoke variant additionally accepts nested child images from user buffers. It copies each image through checked frame tokens before parsing, creates a private root and guarded stack, then publishes a stable callback context to one of the pre-mapped cooperative task slots. Init can wait for a specific child; status copyout precedes reap, and CR3 is restored before kernel wait/reap and teardown. The bounded runtime reclaims scheduler-owned task and TSS entry stacks when tasks are reaped, while process roots retain shared Limine-derived kernel mappings; default boot launches init, but this is not a curated kernel-map policy. Keep the kernel owner alive and immutable for the shared view's lifetime; callers must use a distinct page-table backend for process-owned tables.

### Static ELF64 image validation and page initialization (partial)

`src/elf.rs` parses little-endian x86_64 `ET_EXEC` images without allocation. It bounds the program-header count, load-segment count, and total mapped pages; checks file and virtual arithmetic, page alignment and `p_align` congruence, lower-half canonical ranges, non-overlapping page spans, readable segment flags, W^X, and that the entry point lies in a non-writable executable `PT_LOAD`. It rejects dynamic/interpreter and TLS segments and executable-stack requests. This initial format intentionally requires page-aligned load offsets/addresses and supports at most 64 program headers, 16 load segments, and 64 load pages. `populate_segment_page` copies one load page into an allocator-owned frame through `UserFrameMemory`, zero-filling bytes beyond the file payload. `load_into_process_root` allocates, populates, cache-selects, and maps every load page into an inactive process root. The build reproducibly compiles `crates/rustix-init` as a static ELF64 payload; default boot loads and runs the normal image, while `just user-fault-smoke` builds fault variants and validates process termination/reaping/teardown.

## ABI decisions still pending beyond v1

The initial v1 versioning, error encoding, syscall numbers, register-level request decoding, and assembly-matched syscall context layout are implemented in `src/syscall.rs`. The `int 0x80` path serves ABI-version, descriptor-authorized write, close/dup, spawn, exec, wait, one-page and multi-page mmap/munmap, and exit calls. Spawn copies a user ELF to bounded kernel staging, prepares its private root and stack, and starts it in a reusable task slot; exec replaces the caller's root, image, and stack while preserving PID, descriptors, parent, and children. The process smoke validates nested spawn, five rounds of bounded slot reuse, orphan cleanup, exec replacement and old-image reclamation, and final frame restoration. The process table and wait path remain fixed-capacity at four concurrent processes; this is not a general process-execution service. The table's console descriptors are not general file objects, and there is no read/open support. User faults terminate a process only while the process callback is installed; QEMU covers CPL3 #PF/#GP/#UD/#DE, malformed syscall-return termination, and kernel-fatal coverage for the same architectural vectors. Still open are unbounded task/PID capacity, descriptor-object sharing/close-on-exec, read/open support, wait interruption/signals, clocks, and additional user-visible structure contracts.

## Suggested first user-visible slice

The controlled `no_std` init runs during default boot; QEMU process/fault variants exercise additional lifecycle scenarios. It exercises ABI-version discovery, descriptor duplication/write/close, EFAULT, anonymous mappings, `Vec`/`Box`, and syscall 10 spawn with three user-supplied child images. Init unmaps the source buffer immediately after spawn, checks the fourth spawn fails at capacity, waits for each returned PID, retries after a bad status pointer, then exits for kernel-side wait/reap. All three children validate their two-page zeroed stacks, write a marker, and exit with status 7. This demonstrates bounded user-originated process creation and execution, not a general process-execution environment. The runtime includes bounded `exec`, nested spawn, and reusable/reclaimed task entry stacks; arbitrary-capacity process scheduling and general executable services remain future work. Read/open and general descriptor-object semantics need their own implementation and adversarial tests before any Unix-compatibility claim.
