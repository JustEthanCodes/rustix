# Interrupts and IRQ vector allocation

## Current implementation

`src/arch/x86_64/interrupts.rs` installs the bootstrap GDT, TSS, exception gates for vectors 0–31, device IRQ stubs, and the APIC spurious-vector gate. Kernel-origin exceptions remain fatal. In the opt-in synchronous Ring 3 process probe, noncritical CPL3 exceptions are reported and handed to the installed process callback, which records status `128 + vector`, restores the kernel CR3, and exits through the user-entry trampoline. NMI (#2), double fault (#8), and machine check (#18) remain fatal regardless of saved CPL. QEMU exercises CPL3 #PF, #GP, #UD, and #DE termination in the diagnostic runtime; this is not a general exception or signal mechanism. Maskable interrupts start disabled and are enabled only after the validated APIC route, registered handler, and acknowledgement path are ready.

`src/irq.rs` provides a host-tested, allocation-free token allocator for device vectors `0x20..=0xef` except reserved syscall vector `0x80`; exception vectors and the reserved upper range are also excluded. The IDT overrides `0x80` with a dedicated DPL-3 interrupt gate and assembly stub. The stub rejects CPL0 invocation, saves the full GPR set and x87/SSE state on the TSS entry stack, and dispatches a normalized syscall context with IF clear. Each entered user context owns its continuation RSP, exit status/pending flag, callback context, and kernel FXSAVE image; nested child entry restores the suspended parent's state rather than sharing global entry-depth slots. The per-entry state lets the opt-in scheduler-backed diagnostic suspend one user task in wait while another runs; IF remains clear and timer preemption is not enabled for user contexts. In the opt-in process probe, the dispatcher implements ABI-version discovery, bounded write and wait-status copyout through allocator-owned user-frame copies, exit, and wait on one kernel-prepared child. If that child is running, the scheduler blocks the parent task on a process-exit queue and dispatches the prepared child; child exit wakes the parent, which rechecks status before resuming; the kernel harness later waits/reaps init. This remains a bounded diagnostic with kernel-prepared tasks; it is not userspace spawn/exec or general process lifecycle support. The normal build only exposes ABI-version discovery. `rustix_irq_dispatch` invokes the registered handler, returns for the APIC spurious vector without EOI, and halts on unregistered/unexpected vectors. Device handlers own their EOI. Vector registration is performed with IF clear before the corresponding I/O APIC source is unmasked.

The initial hardware target is single-vCPU QEMU `q35`: validated ACPI/MADT topology, local APIC and I/O APIC, masked legacy PIC routing, MADT-resolved ISA routes, and a periodic 8254 PIT tick near 100 Hz. OVMF smokes validate PIT delivery/EOI, non-yielding timer preemption, x87/SSE state preservation, and UART/keyboard IRQ delivery. Host tests cover vector ownership and PIT/time arithmetic; they do not replace privileged QEMU coverage.

The scheduler is single-vCPU and supports cooperative waits/yields plus PIT-driven timer preemption. The timer handler advances ticks and sends APIC EOI before any scheduling switch. The common IRQ stub saves the interrupted x87/SSE state before Rust dispatch and restores the selected context before `IRETQ`; the context switch keeps aligned per-context FXSAVE areas. IRQ-safe spin locks save and restore the prior IF state, and the global heap uses one; scheduler mutations are separately serialized by masking local interrupts. IRQ/exception handlers remain bounded and allocation-free, and no current IRQ handler acquires the heap lock. SMP, per-CPU state, and physical-hardware validation remain future work.
