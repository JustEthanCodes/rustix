# Testing and verification

## Current checks

`just verify` runs the standard development verification sequence:

1. `just fmt` — fail on formatting differences across the workspace.
2. `just test` — run host-side ACPI parser/traversal, borrowed-page mapping, IRQ vector allocator, PIT rate/time arithmetic, SPSC input-queue wraparound, scheduler, memory-map, mapping-range/PTE-bit policy, frame-allocator, heap, RAM-filesystem, and Crabshell parser tests.
3. `just check` — check the `x86_64-unknown-none` kernel target.
4. `just smoke` — build the pinned hybrid ISO, boot it in QEMU's default BIOS mode, and check that Crabshell reaches its prompt within a deadline.
5. `just uefi-smoke` — boot the same ISO with OVMF and require the copied MADT report, CR3/page-table transition and TLB-flush markers, timer IRQ delivery/EOI, and shell prompt within a deadline.
6. `just active-map-smoke` and `just thread-smoke` — exercise active owned-page mapping/TLB invalidation and (under OVMF) IRQ-save lock IF restoration, cooperative event/wait behavior, timer preemption of non-yielding workers, x87/SSE state preservation, timed sleep while another ready thread repeatedly yields, guarded stacks, and frame-backed heap growth; both restore the default image.
7. `just input-smoke` — under OVMF, type a partial `pwd` over UART, inject ordinary and extended PS/2 scancodes through QMP, require each diagnostic to redraw the prompt and partial line, then finish the command and verify its output. The QMP socket is created under the host temporary directory because WSL `/mnt/c` does not support Unix sockets.

`just frame-smoke` builds an opt-in kernel variant that allocates one `Usable` frame, validates its HHDM address, writes and reads the whole page, clears it, returns it, and checks the prompt in QEMU. It reads the inherited root, walks all pages in the kernel image segments and requested 256 KiB stack span, compares effective PAT/MTRR types for kernel-image/HHDM aliases, and exercises a separate candidate map/unmap/release. The normal boot path in this image also clones the full reachable inherited hierarchy, hardens kernel-image HHDM aliases to text/rodata R/NX and data RW/NX while retaining PAT bits, switches CR3 with active-PCID and global-TLB invalidation, verifies the active root and critical mappings, and exercises the global heap's alignment, reuse, and deterministic exhaustion. The smoke test requires a serial marker confirming the applicable TLB invalidation path. The workflow restores the default release kernel and ISO. These probes rely on Limine's HHDM contract and do not inventory every unrelated mapping or prove physical-hardware correctness. `just fault-smoke` separately builds opt-in kernel variants that deliberately trigger a page fault and an invalid opcode. It requires each QEMU run to report the expected exception (and CR2 for the page fault), avoid the shell prompt, and remain halted until timeout. It then rebuilds and restores the default release kernel and ISO. These are fatal-path diagnostics, not exception recovery tests; diagnostic Cargo features are disabled by default and mutually exclusive.

Keep the ACPI parser, IRQ vector allocator, PIT time arithmetic, Crabshell parser, VFS, memory-map validator, paging policy helpers, frame allocator, and fixed heap independent of hardware so ACPI signatures/checksums/MADT bounds and ACPI page-rounded span authorization, IRQ vector ownership/exhaustion, PIT divisor and elapsed-time arithmetic, syntax, path handling, address and leaf-PTE bit policy, PAT/MTRR policy, storage semantics, frame ownership, HHDM/root-range calculations, allocation alignment, reuse, and exhaustion can be tested without booting. Pure tests validate captured MTRR register snapshots, resolve the Intel SDM Table 11-7 PAT/MTRR combinations for one physical address, select a PAT index that remains uniform across MTRR boundaries in an aligned range, bind that selection to validated mapping metadata before encoding leaves, and walk synthetic four-/five-level page tables including large-page leaves. Host tests also exercise the candidate builder's owned-table walk, clone ownership, 4-/5-level mapping, 2 MiB/1 GiB splitting, permission/cache-bit preservation, active-state mutation/release guard, transactional allocation/prepare rollback, and retryable frame-release failure. Heap tests cover alignment, exact-layout free/reuse, zero-sized rejection, metadata exhaustion, and arena exhaustion. Tests reject malformed state, unsupported discontinuous masks, invalid indexes/ranges, out-of-range addresses, mismatched physical widths, and non-normal caching mode. The pure inherited-table walker does not access hardware tables; the opt-in QEMU reader and candidate backend use checked HHDM addresses. Boot-time QEMU checks a subset of live kernel/HHDM aliases but does not inventory all aliases or prove complete transition safety. Boot separately captures the registers and CR0 caching mode read-only and reports a diagnostic resolution; this is not a page-table or mapping test. The GDT/TSS/IDT and CPU-register paths are privileged kernel code. The temporary ACPI CR3/map/copy/restore path is hardware-only. The 2026-11-07 WSL2 q35 smoke reached the shell but rejected the MADT table span as `NotFullyAcpiBacked`; it did not validate a successful ACPI physical read or CR3 round-trip. QEMU boot and fault-injection checks complement, but do not replace, static review and target builds. Add tests for boundaries and failure behavior when introducing new pure kernel helpers. The kernel binary is not a host test target.

`just uefi-smoke` locates combined OVMF firmware or a matching CODE/VARS pair in standard system directories. `just thread-smoke` uses an opt-in kernel-thread probe, requires the lock-state, cooperative scheduling, non-yielding timer-preemption, and FPU-preservation markers, and restores the default release image. Split firmware uses a fresh temporary copy of the VARS template. `just input-smoke` validates UART RX and PS/2 IRQ delivery/wakeup against the normal default kernel. The OVMF checks require the expected MADT report and CR3-transition markers; install the Ubuntu `ovmf` package if no firmware is found. The BIOS smoke remains separate: if firmware places the RSDT in Reserved memory, the kernel's ACPI validation is expected to fail closed rather than accepting that table span.

## What current checks do not prove

- `cargo check` does not perform a final target link.
- A successful ELF link does not prove the boot protocol is recognized or `_start` is reached.
- Host unit tests do not validate privileged instructions, UART behavior, memory-map pointer validity, page tables, interrupts, or actual hardware. The QEMU boot path exercises the gated EFER/PAT reads and bounded MTRR capture and prints diagnostic summaries, but the prompt smoke assertion does not make those facts a mapping-safety proof.
- The automated QEMU prompt smoke test asserts the cloned CR3 transition, the applicable active-PCID/global-TLB invalidation marker, kernel HHDM alias permissions/cache preservation, heap probe, and shell prompt. The current emulator reports CR4.PGE clear; it exercises the CR3 reload path, not the PGE-toggle global flush path. `just frame-smoke` additionally exercises one allocator-owned frame, inherited paths, kernel/HHDM cache aliases, and a separate candidate mapping through Limine's HHDM contract. The clone preserves Limine's complete reachable hierarchy, but there is no clean-room mapping policy or exhaustive audit of unrelated aliases; emulator tests do not establish physical-hardware behavior. `just fault-smoke` exercises only the controlled page-fault and invalid-opcode fatal paths; it does not test every exception vector or recovery.
- A separate manual QEMU session exercised directory navigation and file create/write/append/read/copy/move/remove operations, including `cp` replacing an existing destination and rejection of `rmdir` on a nonempty directory. This is not exhaustive shell coverage and does not prove persistence across reboot.
- There is no on-disk filesystem integration test, syscall/userspace test, fuzz target, or physical-hardware test.

## Validation policy

For changes to the kernel entry, linker script, boot requests, architecture code, shell, or VFS, run `just verify`. For memory-management and ABI code, add negative tests for overflow, malformed ranges, permission failures, and invalid user pointers before exposing those paths to userspace.

Record commands actually run and any environment limitation in change summaries; never call an unexecuted build “passing.”
