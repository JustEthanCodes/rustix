## Current status

The repository contains a bare-metal `no_std` Rust kernel for `x86_64-unknown-none`. After Limine handoff it validates and copies memory-map metadata into an owned snapshot, captures the executable's physical and virtual bases, complete linker-defined image span, and page-aligned text/rodata/data segment bounds, reports baseline CPUID features, active/maximum address widths, read-only CR0 caching state, gated EFER.NXE/IA32_PAT values, and a bounded MTRR snapshot, seeds a volatile RAM filesystem, and runs Crabshell over the COM1 serial console. Boot-protocol pointers are checked for canonicality using the active 4- or 5-level paging width; physical map bounds and protocol-scoped HHDM range arithmetic are also validated. Crabshell's allocation-free parser is a separate crate; the kernel handles command execution. On 2026-10-16, `just verify` passed in WSL2 Ubuntu 24.04 both in the working tree and from a clean detached worktree with an empty `target` directory; the clean run downloaded and built the pinned Limine host utility, created the image, and passed the bounded QEMU boot to the shell prompt. The serial log showed memory-map and CPU reporting. Hosted CI has not been observed. A separate interactive QEMU session exercised `help`, `ls`, `meminfo`, directory navigation, and file create/write/append/read/copy/move/remove commands. Milestone 0's local exit criteria are met, and Milestone 1's validation criteria are met for the current Limine path. This is a kernel-mode shell, not a user process. A bounded physical-frame allocator is initialized from the validated map and reported by `meminfo`; token ownership and failed-deallocation semantics are documented and host-tested. The boot transition owns an activated clone of Limine's reachable page-table hierarchy, and the initial global heap uses a fixed 256 KiB BSS arena with 128 allocation records. The Limine base-revision 3 HHDM scope and a conservative initial mapping/alias/cache policy are documented. Pure host-tested helpers validate mapping ranges/PTE bits, parse PAT layouts, validate captured MTRR snapshots, combine PAT/MTRR types under normal caching according to Intel SDM Table 11-7, and select a PAT index only when it yields one effective type across an aligned physical range. Boot validates the captured state and prints a diagnostic effective type at PA 0. The transition preserves inherited cache attributes, adjusts kernel-image HHDM aliases to R/NX or RW/NX, and checks the effective PAT index against the inherited mapping. `BootInfo` records raw CR3 and a validated decode of its root physical address and low-bit interpretation. Checked HHDM access is limited to complete allocator-owned usable frames and cloned table frames; the active root owns its cloned table pages while inherited leaf frames remain loader-owned. The complete linker-defined kernel-image span and requested 256 KiB initial boot-stack span are captured and validated; Limine does not report any larger allocation bounds or guard status, so Rustix does not infer a guard page. The heap is fixed-capacity and does not grow from frames; allocation is prohibited in interrupt context. There is no general IRQ subsystem, scheduler, process isolation, persistent filesystem, or Unix compatibility layer. Fatal CPU exceptions have basic GDT/TSS/IDT diagnostics but no recovery. `just fault-smoke` validates a controlled page fault (including CR2) and invalid opcode in QEMU; broader exception coverage and physical-hardware validation remain pending. On 2026-10-21, `just verify` passed after adding CR3 decoding and the pure MTRR resolver, including host tests, target check, release build, ISO creation, and QEMU prompt smoke. On 2026-10-22, `just verify` passed after adding bounded read-only MTRR register capture and validated PAT/MTRR policy resolution. On 2026-10-24, the final `just verify`, `just frame-smoke`, and `just fault-smoke` runs passed after review. QEMU verified the 256 KiB stack request, cloned-root CR3 transition, kernel HHDM alias hardening, heap alignment/reuse/exhaustion probe, and shell prompt; the current emulator reports CR4.PGE clear, so it exercised CR3 invalidation with PGE disabled, while the PGE-toggle path was statically reviewed but not exercised. Milestone 2's local exit criteria are met. These checks do not establish hosted-CI or physical-hardware behavior, a clean-room mapping policy, or exhaustive alias coverage.

## Documentation conventions

- **Implemented** means present in the repository and checked by current code or tests.
- **Planned** means an architectural direction, not a stable ABI or delivered capability.
- Any future ABI proposal must state versioning, error behavior, memory ownership, and compatibility expectations before it is treated as stable.
